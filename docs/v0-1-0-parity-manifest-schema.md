# KLE v0.1.0 Parity Manifest Schema

## Status

This document defines the fail-closed data contracts for the KatanA editor
parity gate. It is a design contract, not evidence that any leaf is complete.
Generation and validation are partially implemented. Canonical binding integration
does not prove semantic closure, native execution, or publication.

## Scope and Identity

Every release candidate must produce six canonical, versioned JSON artifacts:

```text
source-closure.json
action-origins.json
branch-catalog.json
leaf-manifest.json
execution-record.json
storybook-artifacts.json
```

All six artifacts must contain these identical root fields:

```json
{
  "schema_version": "1",
  "katana_revision": "<full git SHA>",
  "katana_tree_fingerprint": "sha256:<hex>",
  "katana_external_ui_fingerprint": "sha256:<hex>",
  "user_mandated_extensions_fingerprint": "sha256:<hex>",
  "source_universe_fingerprint": "sha256:<hex>",
  "requirement_source_aliases_fingerprint": "sha256:<hex>",
  "kle_tree_fingerprint": "sha256:<hex>",
  "kuc_tree_fingerprint": "sha256:<hex>",
  "release_profile_matrix_fingerprint": "sha256:<hex>",
  "generator_fingerprint": "sha256:<hex>",
  "generated_at_utc": "<RFC3339 UTC>"
}
```

The KatanA revision must equal the revision recorded in
`v0-1-0-katana-editor-source-universe.md`. A hash, schema version, or revision
mismatch is a release failure. A consumer must reject a manifest generated by
a different source tree, KLE tree, KUC tree, or generator binary.

`release_profile_matrix_fingerprint` is the hash of the canonical ordered
`macos-latest`, `windows-latest`, `ubuntu-latest` profile records. Each record
contains its actual runner label, `rustc -vV` host triple, complete
`rustc --print cfg` output hash, resolved Cargo feature/dependency graph hash,
and lockfile hash. The source closure is the union of the three profile graphs;
an absent profile, a default-host substitute, or a profile mismatch is invalid.

## Explicit User-Mandated Extension Input

`docs/v0-1-0-user-mandated-leaves.json` is a seventh, immutable generator
input; it is not a generated parity artifact and therefore is not part of the
six-artifact set above. Its schema is exactly the following shape:

```json
{
  "schema_version": "1",
  "extensions": [{
    "leaf_id": "replace.current",
    "katana_direct_ui_origin": false,
    "kuc_component": "SearchStrip",
    "katana_host_route": {
      "action": "AppAction::ReplaceText",
      "dispatch": "crates/katana-ui/src/app/action/dispatch.rs",
      "handler": "DocumentEditOps::handle_replace_text"
    },
    "requirement_anchor": "docs/v0-1-0-editor-requirements.md#explicit-user-mandated-extensions",
    "prohibitions": ["..."]
  }]
}
```

The root key is `extensions`, not `leaves`. The generator must reject a missing
or additional root key, a schema version other than `1`, duplicate or
unregistered `leaf_id` values, any entry other than `replace.current` and
`replace.all`, a true `katana_direct_ui_origin`, a route mismatch, or a
non-canonical array order. Its SHA-256 over the raw input bytes is the
`user_mandated_extensions_fingerprint` carried by all six generated artifacts.
An empty list, a count-only assertion, or a category/wildcard entry is invalid.

## Source Closure

`source-closure.json` records every reachable KatanA reference file and every
lock-pinned external UI semantic dependency. It starts
from the direct editor and integration roots in the source-universe ledger,
then follows Rust AST module, item, call, action-dispatch, state/data-refresh,
generic-presentation, and test-oracle edges.

```json
{
  "profiles": [{
    "id": "macos-latest",
    "fingerprint": "sha256:<hex>",
    "rustc_host_triple": "<rustc -vV host>",
    "rustc_cfg_sha256": "sha256:<hex>",
    "cargo_resolution_sha256": "sha256:<hex>",
    "active_edge_ids": ["edge:<id>"],
    "inactive_cfg_edges": [{
      "edge_id": "edge:<id>",
      "predicate": "target_os = windows",
      "span": "katana:<path>:<span>"
    }]
  }, {
    "id": "windows-latest",
    "fingerprint": "sha256:<hex>",
    "rustc_host_triple": "<rustc -vV host>",
    "rustc_cfg_sha256": "sha256:<hex>",
    "cargo_resolution_sha256": "sha256:<hex>",
    "active_edge_ids": ["edge:<id>"],
    "inactive_cfg_edges": [{
      "edge_id": "edge:<id>",
      "predicate": "target_os = macos",
      "span": "katana:<path>:<span>"
    }]
  }, {
    "id": "ubuntu-latest",
    "fingerprint": "sha256:<hex>",
    "rustc_host_triple": "<rustc -vV host>",
    "rustc_cfg_sha256": "sha256:<hex>",
    "cargo_resolution_sha256": "sha256:<hex>",
    "active_edge_ids": ["edge:<id>"],
    "inactive_cfg_edges": [{
      "edge_id": "edge:<id>",
      "predicate": "target_os = macos",
      "span": "katana:<path>:<span>"
    }]
  }],
  "files": [{
    "path": "crates/katana-ui/src/views/panels/editor/text_edit.rs",
    "sha256": "sha256:<hex>",
    "incoming_edges": [{
      "from": "crates/katana-ui/src/views/panels/editor/ui.rs",
      "kind": "call",
      "from_symbol": "EditorContent::show",
      "span": { "start_line": 1, "end_line": 1 }
    }],
    "classification": "editor_behavior",
    "classification_rationale": "..."
  }],
  "external_ui_semantic_dependencies": [{
    "package": "egui",
    "version": "0.36.1",
    "source": "registry+https://github.com/rust-lang/crates.io-index",
    "package_checksum": "sha256:<hex>",
    "source_files": [{ "path": "<registry-relative>", "sha256": "sha256:<hex>" }],
    "symbols": ["TextEdit::multiline"],
    "katana_invoking_edges": ["edge:<id>"],
    "direct_semantic_edges": [{
      "from_symbol": "TextEdit::show",
      "kind": "call",
      "source_file": "egui/src/widgets/text_edit/builder.rs",
      "span": "egui:<path>:<start>-<end>",
      "target_symbol": "TextEditState::load"
    }],
    "replacement_leafs": ["clipboard.text-copy-selection"],
    "fingerprint": "sha256:<hex>"
  }],
  "unresolved_edges": []
}
```

`direct_semantic_edges` is a deterministic, authenticated direct-call diagnostic
input to the external UI fingerprint. It does not establish transitive closure or
make the dependency complete. `unresolved_edges` must be empty. Dynamic dispatch, macros, generated code,
and external boundaries require a resolved destination or a documented
host-boundary rationale with an exact source span. A behavior-bearing external
UI dependency instead requires its exact lock/package/source/symbol record and
KUC replacement leaf. Missing files, missing hashes, self-reported static
counts, or a deferred/nonexistent adapter are invalid.

The `profiles` array has exactly the canonical three profile IDs in order. Each
edge must appear active in its applicable profile(s), inactive with its exact
`cfg` predicate in the others, or be explicitly profile-independent. A profile
record cannot reuse another runner's graph or omit a `cfg` edge merely because
the current test target did not compile it.

## Action Origins

`action-origins.json` prevents the generator from treating every KatanA
`AppAction` definition as a KLE-visible feature. It backward-traces every
reachable action construction from its source input/callback/shortcut origin
and binds that result to the forward definition/dispatch/handler closure.

```json
{
  "actions": [{
    "action_id": "katana:AppAction::CloseDocument",
    "definition_span": "katana:<path>:<span>",
    "construction_sites": ["katana:<path>:<symbol>:<span>"],
    "origin_classification": "editor_direct_ui",
    "active_profile_ids": ["macos-latest", "windows-latest", "ubuntu-latest"],
    "origin_input": {
      "kind": "pointer",
      "source_span": "katana:<path>:<span>"
    },
    "forward_route": [
      "katana:<dispatch-span>",
      "katana:<handler-span>",
      "katana:<effect-span>"
    ],
    "kle_leafs": ["document.tab-close.clean"],
    "fingerprint": "sha256:<hex>"
  }, {
    "action_id": "katana:AppAction::ForceCloseDocument",
    "definition_span": "katana:<path>:<span>",
    "construction_sites": [],
    "origin_classification": "unmounted_editor_state_continuation",
    "predecessor_actions": ["katana:AppAction::CloseDocument"],
    "state_span": "katana:<pending-state-span>",
    "no_renderer_or_shortcut_rationale": "katana:<source-span-set>",
    "kle_leafs": [],
    "fingerprint": "sha256:<hex>"
  }],
  "unresolved_action_origins": []
}
```

`origin_classification` is exactly one of `editor_direct_ui`,
`editor_shortcut`, `editor_host_continuation`, `user_mandated_extension`,
`unmounted_editor_state_continuation`, `host_only`, or `unresolved`.
`unresolved_action_origins` must be empty. An `unmounted_editor_state_continuation`
is valid only with an exact state span, predecessor action, and exhaustive
fixed-revision renderer/shortcut search rationale; it has no KLE request,
Storybook stage, or passing leaf. The parity gate rejects an action origin
without source spans, an action-visible leaf without an `editor_direct_ui` or
`editor_shortcut` origin, and any KLE/KUC control that corresponds only to an
unmounted or host-only action. A `user_mandated_extension` is valid only when
its exact requirement ID/span is registered in the physical requirements
document, its KUC generic control has a public RawInput/AccessKit origin, and
its unchanged KatanA definition/dispatch/handler/effect route is complete. It
must be reported separately from source-origin parity and cannot authorize any
other extension by category or count.

## Branch Catalog

`branch-catalog.json` expands each decisive source branch, guard, match arm,
early return, and visible/action/accessibility state transition reachable from
the closure:

```json
{
  "branches": [{
    "branch_id": "katana:<path>:<symbol>:<span>:<ordinal>",
    "file": "crates/katana-ui/src/views/panels/editor/paste.rs",
    "symbol": "EditorPasteOps::intercept_clipboard_image_paste",
    "span": { "start_line": 1, "end_line": 1 },
    "kind": "guard",
    "condition": "<normalized AST condition>",
    "active_profile_ids": ["macos-latest"],
    "inactive_profile_predicates": [{
      "profile_id": "windows-latest",
      "predicate": "target_os = macos"
    }],
    "outcomes": ["leaf:<id>", "helper:<id>"],
    "incoming_edges": ["edge:<id>"],
    "source_excerpt_sha256": "sha256:<hex>"
  }],
  "unclassified_branch_ids": []
}
```

Every branch must classify to one or more leafs or to a helper with a
non-visible, non-action rationale and all callers. `unclassified_branch_ids`
must be empty. Text markers, fixed required counts, aggregate groups, or shared
selectors are not branch records.

Every profile applicability set must be nonempty and exhaustive over the
canonical release matrix. A platform-specific branch has individually
classified active and inactive outcomes; a generic branch records all three as
active. A branch whose profile condition, outcome classification, or source
excerpt changes without updating the profile set is invalid.

## Leaf Manifest

`leaf-manifest.json` is the release checklist. One row means one observable
behavior, never a toolbar/menu/category aggregate:

The mandatory `canonical_binding` object contains `inventory`, `t2`, `t3`, and
`structured`. These are complete structured reports, not optional sidecars or
matched-only extracts. `inventory.requirements_sha256` binds the compiled
requirements input. Loading reconstructs the inventory and T2 from that input
and the source/branch artifacts, validates T3 parent/root/fingerprints/source
facts, and reconstructs the structured report including every unmatched and
unresolved item. Release validation separately rejects unclassified populations.
Integrity agreement alone does not prove the completeness of T3 source scanning.

Each projected leaf has a mandatory `source_candidate_fingerprint`. Its ID,
requirement origin, source branches and profiles must match exactly one structured
candidate; missing, extra or duplicate projections are invalid. The producer
emits `candidate` status and unresolved semantic fields. Later semantic enrichment
requires independent evidence; changing a status string is not sufficient.
The leaf example below illustrates the eventual evidence-bearing form; the
mandatory full reports and common root fields are omitted for readability.

```json
{
  "leafs": [{
    "leaf_id": "source-candidate:sha256:<candidate hex>",
    "source_candidate_fingerprint": "sha256:<candidate hex>",
    "requirement_origin": {
      "kind": "structured_requirement_binding",
      "span": "katana:<path>:<span>"
    },
    "source_branches": ["katana:<path>:<symbol>:<span>:<ordinal>"],
    "action_origin_ids": ["katana:AppAction::AuthorMarkdown"],
    "required_profile_ids": ["macos-latest", "windows-latest", "ubuntu-latest"],
    "visible_path": ["editor", "floating-toolbar", "bold"],
    "state_preconditions": ["non_empty_selection", "editable"],
    "kuc_component": "FloatingCommandToolbar",
    "kle_public_show_signature": "<verified public KLE entry>",
    "kle_opaque_transit": "opaque-authoring-target activation (target/revision/correlation only)",
    "declared_effect_kind": "in_process_host_effect",
    "host_e2e": {
      "state": "passing",
      "adoption_issue_url": "https://github.com/HiroyukiFuruno/KatanA/issues/336"
    },
    "execution_id": "run:<id>",
    "storybook_stage_id": "leaf:toolbar.bold.selection",
    "status": "passing"
  }]
}
```

The intended semantic classes for `declared_effect_kind` are `kuc_retained_ui_effect`,
`in_process_host_effect`, or `native_external_host_effect`.
For KLE publication, `kuc_retained_ui_effect` requires a current KUC state
transition and the corresponding KLE-owned no-mutation outcome. KatanA host
observations are required only by post-publication `downstream-full` validation.
That later gate requires the actual KatanA effect for the other classes, except
an `editor_shortcut` recorded with `katana_shortcut_router`
input origin, which requires the independent physical-router and correlated KUC
proof described below instead of a KLE transit. The leaf is invalid unless all referenced branch, KUC current-frame
record, AccessKit node, class-appropriate transit/effect, execution, and media
stage exist and agree. A source marker, `always` precondition, generic host
description, downstream simulator result, or Storybook-only action is invalid.
For a registered user-mandated extension, `requirement_origin.kind` is
`user_mandated_extension`; it instead names the immutable requirement span and
the exact host handler branch. It still requires every KUC/KLE/host/execution
proof field and is never counted as a KatanA direct-UI leaf.
`host_e2e.state` is either `downstream_required` or `passing`. `downstream_required`
is valid for the pre-publication KLE gate, must name KatanA #336 exactly, and
must not claim a KatanA host execution; it never means that the host work is
complete. `passing` requires the matching host execution record for every profile
in post-publication `downstream-full`. KLE execution evidence is validated in its
separate release artifact. `candidate`, `pending`, and `failing` leaf statuses
cannot satisfy publication: every required KLE/KUC behavior must be proven.

## Execution Record

`execution-record.json` binds a leaf to one same-run, public-input proof:

```json
{
  "runs": [{
    "execution_id": "run:<id>",
    "leaf_id": "toolbar.bold.selection",
    "release_profile_id": "macos-latest",
    "release_profile_fingerprint": "sha256:<hex>",
    "input_origin": "kle_kuc_root",
    "raw_input_trace_sha256": "sha256:<hex>",
    "show_locator": "EguiLanguageEditor::show",
    "kuc_root_frame_sha256": "sha256:<hex>",
    "accesskit_snapshot_sha256": "sha256:<hex>",
    "katana_physical_input": {
      "source_span": "katana:<path>:<span>",
      "katana_frame_sha256": "sha256:<hex>",
      "kind": "accesskit_pointer",
      "target_accesskit_node_id": "<id>",
      "target_role": "button",
      "target_name_sha256": "sha256:<hex>",
      "target_bounds_sha256": "sha256:<hex>"
    },
    "typed_event_trace_sha256": "sha256:<hex>",
    "declared_effect": {
      "kind": "in_process_host_effect",
      "assertion_sha256": "sha256:<hex>"
    },
    "result": "passing"
  }]
}
```

For `input_origin: "kle_kuc_root"`, the trace begins at public `RawInput`,
crosses exactly one public `EguiLanguageEditor::show`, and records KUC's
retained opaque root. For `kuc_retained_ui_effect`, it additionally records the
prior/current KUC state, the no-host-action assertion, and a read-only
unchanged-host observation.

An `editor_shortcut` may instead use `input_origin:
"katana_shortcut_router"`. That record contains the physical KatanA key-input
trace, active context, availability result, reservation/ordering decision,
exactly-one action and handler/effect assertion, plus the SHA-256/revision of a
same-run correlated KUC root/AccessKit focus-or-retained-input record. It has
no `show_locator` and no typed KLE request. This is an explicit non-mounted
evidence join: it proves neither a KLE shortcut parser nor KLE rendering inside
KatanA. A shortcut record missing either side, with a direct action injection,
or claiming `KLE RawInput -> shell_ui_shortcuts` is invalid.
Ordinary content updates must reach unchanged KatanA `UpdateBuffer`; replacement
must reach `ReplaceText`. External host changes only flow from KatanA back to
KLE. A clipboard request requires a correlated, one-time host resolution. A
dropped, duplicated, injected, simulated, or locally completed event is invalid.

`native_external_host_effect` records the separate native-driver trace, KatanA
action/frame trace, and same-run document/asset/no-mutation assertion. Pending
dialog state, ignored tests, fixed sleeps, coordinate clicks, manual steps, or
payload injection cannot produce a passing record.

Every leaf is executed and recorded independently for `macos-latest`,
`windows-latest`, and `ubuntu-latest`. A result from one profile cannot satisfy
another profile. Text/emoji leaves additionally record the KUC-resolved
color-emoji face identity and loaded-file SHA-256; `SansSerif`, a missing
face, or a skipped profile is invalid.

For `in_process_host_effect` and `native_external_host_effect`, a
`katana_physical_input` record is mandatory. Its source span, current-frame
target, and action/handler trace must agree with the source closure. Pointer
bounds are valid only as the hash of the AccessKit-discovered target in that
same frame; hard-coded/replayed coordinates, raw semantic payloads, and direct
action calls are invalid. `editor_shortcut` records the analogous physical key
target/context/availability record under `katana_shortcut_router`.

## Storybook Artifact Manifest

`storybook-artifacts.json` binds review media to the same execution record:

```json
{
  "stages": [{
    "stage_id": "leaf:toolbar.bold.selection",
    "execution_id": "run:<id>",
    "release_profile_id": "macos-latest",
    "release_profile_fingerprint": "sha256:<hex>",
    "frame_number": 17,
    "png_path": "frames/0017-toolbar-bold-selection.png",
    "png_sha256": "sha256:<hex>",
    "dimensions": { "width": 1, "height": 1 },
    "opaque_kuc_root_sha256": "sha256:<hex>",
    "accesskit_snapshot_sha256": "sha256:<hex>"
  }],
  "contact_sheet_sha256": "sha256:<hex>",
  "gif_decoded_frame_hashes": ["sha256:<hex>"],
  "mp4_decoded_frame_hashes": ["sha256:<hex>"]
}
```

Stages are numbered, nonempty, fresh, non-duplicate PNGs from the KUC opaque
root frame only. Contact sheet, GIF, and MP4 decode hashes must equal the PNG
sequence in order. A fallback renderer, minifb, egui shape count, fixture
glyph, or a second KLE composition invalidates the artifact.

Artifacts are profile-scoped. The manifest contains a complete ordered stage
set for every release profile and never merges cross-profile pixels into one
acceptance hash. For exact `⭐️` VS16 leaves, each profile stage stores the
isolated star crop hash, chromatic-pixel assertion, same-config `☆` control
crop hash, and resolved KUC color-face SHA-256.

## Gate Rules

The parity checker must reject all of the following:

- an absent or stale canonical artifact;
- an unresolved source edge or unclassified decisive branch;
- a leaf not backed by an exact source branch;
- a shared selector, aggregate leaf, or static leaf/file count;
- a KLE-local geometry, glyph, hit-test, compositor, or external payload path;
- an `Unsupported` result for a required leaf;
- incomplete or mismatched KUC, KLE, KatanA, and Storybook evidence;
- a passing media record without its matching execution record and host effect.

The gate has no exclusions, allowlists for old paths, fallback success cases,
or completion override. The only successful release result is an empty set of
unresolved edges, unclassified branches, pending leafs, failing leafs, and
evidence mismatches.
